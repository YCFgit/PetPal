## 安全约束与架构取舍

内存事务队列只保证同一个 Node.js 进程内的开发行为。MySQL 适配器按记录查询和写入，创建订单时锁定用户、报价和时段，并在同一事务写入订单、名额、资源引用、事件和幂等记录；仍需真实环境压测和故障注入后才能评估生产能力。

报价有效期默认 5 分钟，未支付期限默认 15 分钟，是待评审的开发参数，不是用户协议或已批准的取消政策。示例定价仅为测试数据。真实部署前应将已批准的参数集中配置并纳入规则快照。

取消/超时释放只允许 `paymentChannelSubmitted=false` 的订单；接入支付时必须先持久化支付尝试/提交事实，再调用外部渠道。进程崩溃或渠道结果未知时要保守处理，不能将状态复位为未提交并直接释放名额。不能因为没有收到成功回调就认定没有扣款。

开发 Bearer token 固定映射到一个本地用户，不能用它实现多租户或微信登录。示例资料默认关闭；只有本地环境允许启用。内存数据无审计持久性，不能用于真实地址、入户密码或任何生产资金记录。

资料删除只移除当前资料项，不清除已保存报价/订单中的快照，不代表已履行个人信息删除请求。待支付订单引用资料时返回 `RESOURCE_IN_USE`；取消或超时释放后允许删除。更新资料不修改已建订单，也不是订单改址/改宠物接口。地址区域暂以已配置的有效服务与时段判断，尚无独立区域目录或地理围栏；这一开发校验不是实际服务范围核验。

受控沙箱对本机 TCP 和 socket 返回权限错误；用户已在系统终端完成数据库预建授权、迁移、MySQL 集成测试、HTTP 冒烟及 API 重启后的订单查询。
